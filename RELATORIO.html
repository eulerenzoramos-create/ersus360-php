ERSUS360 · PHP 8.4

Reescrita completa do sistema de gestão em saúde da SMS Apuí/AM em PHP 8.4 + MySQL 8.4 LTS. Substitui FastAPI + SQLite com arquitetura layered, persistência confiável e deploy via Railway.

🏗 Visão Geral

Stack técnica e decisões de arquitetura

⚙️
Runtime
Backend
  • PHP 8.4 (typed properties, match, fibers)
  • MySQL 8.4 LTS (utf8mb4, DECIMAL(14,2))
  • PDO com prepared statements reais
  • PSR-4 autoload + PSR-12 code style
🔐
Segurança
Auth + Dados
  • JWT HS256 via firebase/php-jwt
  • bcrypt cost=12 (password_hash)
  • Isolamento por município por perfil
  • Credenciais apenas em Railway env vars
📦
Dependências
composer.json

  • monolog/monolog ^3.7
  • vlucas/phpdotenv ^5.6
  • dompdf, phpspreadsheet
🚀
Deploy
Infraestrutura

Camadas e responsabilidades

📁 ersus360-php/ · estrutura de camadas
core/ ← infraestrutura: App, Router, Database, Container, Request, Response, Logger app/Controllers/ ← recebem HTTP, delegam para Services/Repositories app/Services/ ← lógica de negócio (FnsService, FolhaService, PortariasService...) app/Repositories/← SQL via PDO, nunca expõem senha_hash ao caller app/Integrations/← clientes HTTP externos (ConsultaFns, ApiFns, DOU, Resend) app/Middleware/ ← AuthMiddleware (JWT) + PermissaoMiddleware (módulo) app/Jobs/ ← cron jobs CLI: FnsSync, PortariasSync app/Exceptions/ ← HttpException (status + extra + toArray) routes/api.php ← registro de todas as rotas com grupos e middleware database/ ← migrations SQL (001–015), seeders, migrate.php runner tests/Unit/ ← PHPUnit: JwtServiceTest, PermissaoServiceTest, AuthServiceTest docker/ ← nginx.conf, supervisord.conf

🚢 Passos para Deploy no Railway

Sequência de comandos e ações

1
Instalar dependências PHP
cd ersus360-php && composer install
2
Configurar .env local
copy .env.example .env e preencher DB_*, JWT_SECRET, APP_KEY
3
Criar banco MySQL no Railway
Railway Dashboard → New Service → MySQL 8.x → anotar host, porta, user, pass, dbname
4
Rodar migrations + seeder
php database/migrate.php --seed — cria as 15 tabelas e insere Apuí/AM
5
Deploy no Railway (Docker)
Railway detecta o Dockerfile automaticamente. Configurar as env vars no painel e fazer deploy.
6
Testar health check
GET https://seu-app.railway.app/api/health → deve retornar {"status":"ok"}
🔄 Migração dos Dados do Sistema Python

Sequência crítica — antes de desligar o sistema atual

⚠ Urgente: O sistema Python armazena presença em /tmp que é apagado a cada redeploy Railway. Exportar antes de qualquer novo deploy.
1
Exportar /tmp do Railway (Python)
Railway console → cat /tmp/ersus_folha_presenca.json → copiar conteúdo
2
Copiar folha_referencia.json
Copiar backend/data/folha_referencia.json para ersus360-php/storage/data/
3
Importar presença via API
POST /api/folha/importar-legacy com o JSON exportado → migra para banco MySQL
4
Verificar integridade dos dados FNS
As chave_unica SHA-256 são idênticas ao Python — nenhum duplicado será inserido
